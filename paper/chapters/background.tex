\section{Preliminaries}
\label{sec:background}

\subsection{Control-Flow Graphs}
\label{subsec:cfg}

A compiler represents the execution structure of a program as a CFG.

\begin{definition}[Control-Flow Graph]
A CFG is a directed graph $G = (V, E)$ where each node $v \in V$ is a \emph{basic block}, a straight-line sequence of instructions with a single entry and a single exit point, and each edge $(u, v) \in E$ represents a possible transfer of control from block $u$ to block $v$~\cite{allen_1970}.
\end{definition}

\noindent The topology of CFGs is determined by a program's control structure.
Sequential statements produce linear chains of basic blocks, while additional control constructs such as conditionals, loops and function exits make the flow between nodes more complicated.
For example, loops create edges that point back to earlier blocks in the graph~\cite[Ch.~7]{muchnick_1997}.

\subsection{Treewidth}
\label{subsec:treewidth}

Treewidth is a graph parameter that measures how tree-like a graph is~\cite{bodlaender_1993}.
Many computational problems that are NP-hard on general graphs can be solved efficiently on graphs with small treewidth, by applying dynamic programming on a tree decomposition of the graph~\cite{bodlaender_1988}.
We first define tree decompositions, then treewidth in terms of them.

\begin{definition}[Tree Decomposition]
A \emph{tree decomposition} of a graph $G = (V, E)$ is a pair $(X, T)$, where $T$ is a tree and $X = \{X_2, \ldots, X_n\}$ is a family of subsets of $V$ (called \emph{bags}), one per node of $T$, satisfying:
\begin{itemize}
	\item $\bigcup_{i} X_i = V$: every vertex of $G$ appears in at least one bag.
	\item For every edge $(u, v) \in E$, there exists a bag $X_i$ such that $u \in X_i$ and $v \in X_i$.
	\item For every vertex $v \in V$, the set of bags $\{X_i \mid v \in X_i\}$ forms a connected subtree of $T$.
\end{itemize}
The \emph{width} of a tree decomposition is $\max_i |X_i| - 1$~\cite{robertson_1986}.
\end{definition}

\begin{definition}[Treewidth]
The \emph{treewidth} of a graph $G$ is the minimum width over all valid tree decompositions of $G$~\cite{robertson_1986}.
\end{definition}

\noindent A treewidth of~1 corresponds to a tree.
As treewidth increases, the graph becomes less tree-like and structurally more complex.

\paragraph{Relevance and CFG connection}
Graphs with bounded treewidth allow many hard computational problems to be solved efficiently~\cite{thorup_1998}.
The runtime of such algorithms depends exponentially on the treewidth, but only polynomially on the number of vertices, making them feasible for graphs with small treewidth~\cite{bodlaender_1988}.

In the context of programs, CFGs serve as input graphs for treewidth analysis.
Analysing the treewidth of a CFG provides a way to quantify the program's structural complexity.
Programs with simpler, more structured control flow generally have lower treewidth, whereas programs with more complex control flow tend to have higher treewidth~\cite{thorup_1998}.
